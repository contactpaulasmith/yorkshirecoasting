Notes

1.Paula accesses a password-protected /admin section of the live website to draft/publish Local Guide entries, manage reviews, and view property settings. The password is hardcoded in the frontend and provides basic access control only.
2.Replit (replit.com) is the cloud development environment where the codebase lives and where the AI Agent makes all code changes. It also provides the deployment infrastructure. Two separate services run here: the static website and the API server.
3.GitHub (github.com, owned by Microsoft) stores the canonical source code at contactpaulasmith/yorkshirecoasting. Every change the Agent makes is committed and pushed here. This is the permanent backup and version history of the site.
4.All site content — properties, Local Guide entries, reviews — is seeded from initialData.ts (a file in the codebase) into the visitor's browser localStorage on first load. Admin edits persist only in that browser; they are lost if the browser cache is cleared or a different device is used. Permanent changes must go through the Agent updating the source file.
5.Replit Autoscale hosting scales the application up and down based on traffic, running only when requests arrive. It handles TLS (HTTPS), health checks, and serves the app at a .replit.app domain. The static site and API server are deployed as separate services within the same Replit project.
6.At deploy time, Vite (a build tool) compiles the React TypeScript source into optimised, minified static HTML/CSS/JavaScript files. These compiled files — not the source code — are what visitors actually receive. The build runs inside the Replit environment using the pnpm package manager.
7.The website is a Single-Page Application (SPA) built with React. All page navigation happens client-side in the browser with no round-trips to the server. UI components use Radix UI (accessible primitives) styled with Tailwind CSS. Routing uses the Wouter library.
8.An Express.js API server (Node.js) runs alongside the static site under the /api/* path. Currently it serves only a /api/healthz health-check endpoint used by Replit's infrastructure. It is built and ready to be extended with database-backed endpoints in future.
9.The Contact page form submits directly from the visitor's browser to Formspree (formspree.io) — a third-party form backend service. Formspree receives the submission and forwards it to Paula's email address. No data passes through the Replit servers for form submissions.
10.Airbnb is the booking platform for both properties. The website links directly to the existing Airbnb listings (room IDs 1880508 and similar). Bookings, payments, and guest communication are managed entirely within Airbnb — the Yorkshire Coasting site does not handle any booking transactions.
11.English Heritage manages Whitby Abbey and Scarborough Castle. The Local Guide links directly to the English Heritage website for visitor information and ticket booking for these attractions.
12.TripAdvisor is used in two ways: (a) as the destination for "Visit Website" links on many food & drink entries in the Local Guide, and (b) as an image source — several restaurant photos are loaded directly from TripAdvisor's CDN servers.
13.Images throughout the site are loaded directly from external CDN servers: Unsplash (stock beach/landscape photos), TripAdvisor CDN (restaurant photos), Airbnb CDN (property photos), and individual venue websites. No images are stored within the Replit project itself, except one local image (/images/secret-realm.jpg).
